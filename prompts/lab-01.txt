I'm creating a reference solutoin for a workshop on AWS workshop studio for reInvent. It is a simple multi-tenant SaaS e-commerce application. It has the following: 

1. Control plane: Will have micro-services that help to manage, operate the SaaS, tenant provisioning, tenatn de-provisioning
2. applicaiton plane that provides e-commerce experience. micro-services: product, order, payment (with payment gateway mocked). 
3. 2 tiers : Basic ($29), Premium ($99)

Tenants (vendors) can self-onbaord in the SaaS via a landing page. Only Tenant admins can see the "Tenant admin panel in the SaaS app, which has functionalities such as onboarding new tenant users, so Tenant admins can onboard tenant users, and they can create products (with name, description, images, etc etc). Those users can log in -> create orders from products in a cart and then Place Order. 

Tech Stack : Use AWS servereless Stack including API Gateway, Cognito. Control plane services and applicaiotn plane services are communicating each other via AWS EventBridge. Application plane actions such as order.placed, payment.completed should not have an EventBridge, instead, as a simple sequential execution (as this is only for testing). Product DB - shared, order & payment DBs - Silo. All infra coding on CDK on Typescript. All business logic is on Python. all CDK projects in ./infra/ folder. Need 3 front-end apps : landing-page, saas-app, saas-admin-app. Place all microservices into ./src/ folder. 

Let me know the outline. Do not worry about workshop modules etc as I will take care of the workshop lineup/labs seperately. I really like the following folder structure.
